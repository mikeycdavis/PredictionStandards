## What

Move `VERSION`, `package.json.version`, the integrity baseline and the README declaration to 1.2.0,
extend the version-agreement test to cover the README, and re-adopt this repository against the
pack it publishes.

## Why

The README had read `Version 1.0.0` through an entire release. The correct response to a sentence
that drifted is to extend the agreement proof, not to edit the sentence.

## Notes

The new guard **matches** the declaration rather than searching for the number: `includes(version)`
would have gone green on the stale sentence the moment the right number appeared anywhere else on
the page. Falsified before being trusted — reverting the README fails it, restoring it passes.

`reviewedOn` deliberately did not move: the protections were not reviewed again, and moving that
date to match a release would assert a review that did not happen. The three
`artifacts/adoption/*.yml` records stay frozen at 1.0.0, because that is what those runs used.

Re-adoption landed **after** the identity bump so that no commit in history carries a policy naming
a version that does not exist. `75d1840` corrected artifacts dated 2026-08-23 to 2026-08-25 — caught
because the container run stamps the date the work actually happened.
