## What

Decide the version-resolution contract, then make the evaluator hold to it: what counts as a
resolvable framework version, what legitimate historical pinning means, and what disposition a
policy receives when its declared version cannot be resolved.

## Why

The contract question has to be answered before any code is written, because the obvious
implementation is wrong. Requiring `policy.standardVersion` to equal the current `VERSION` would
reject the pack's own adoption archives, which pin `1.0.0` deliberately and are frozen on purpose.
An enforcement rule written before the semantics are settled would encode that error.

## Notes

Deliberately scoped as a contract question rather than a fix. The disposition is already
constrained by the schema — a configuration error, **not** a compliance failure — which means the
answer has to reach the aggregate status through whatever path represents "this run could not be
evaluated", not through a rule failure.

Implementation is **not filed yet**, and that is intentional: its shape is an output of FE-14, not
an input to it.
